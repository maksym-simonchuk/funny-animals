# funny-animals-enricher

CLI+API инструмент для сборки локального датасета коротких видео с животными: сбор из легальных источников → обработка (качество/дедуп/детекция) → экспорт в ML-форматы.

## 1. Что это

Собирает видео двумя способами:

- **Pexels API**, **Pixabay API** — поиск по ключевому слову через официальные API этих сервисов (нужен ключ разработчика). Openverse в проект не вошёл: его публичный API индексирует только изображения и аудио, видео-эндпоинта нет.
- **yt-dlp по явно заданному списку URL** (`fetch --urls urls.txt`) — вы сами перечисляете ссылки, скачивание идёт через стандартный `yt-dlp` без логина и без прокси.

**Явно НЕТ и не будет в проекте:** массового скрейпа Instagram по хэштегам, логина в соцсети, ротации прокси/User-Agent, обхода антибот-защит. Это нарушение условий использования (ToS) платформ. `fetch` скачивает **только** то, что вы сами вписали в `urls.txt` — ответственность за то, какие URL туда попадают, и за соблюдение лицензий скачанного контента, лежит на пользователе.

## 2. Установка

Требуется **Python 3.12** и системный **ffmpeg** (`ffprobe`/транскод).

```bash
uv venv --python 3.12 .venv
uv pip install -r requirements.txt
```

Проверить ffmpeg: `ffmpeg -version`. Если нет — поставить через пакетный менеджер ОС (`brew install ffmpeg`, `apt install ffmpeg`, …). В Docker-образе ffmpeg уже установлен.

## 3. Ключи API

Скопируйте `.env.example` в `.env` и заполните:

```bash
cp .env.example .env
```

- `PEXELS_API_KEY` — регистрация разработчика: https://www.pexels.com/api/
- `PIXABAY_API_KEY` — регистрация разработчика: https://pixabay.com/api/docs/

Оба коллектора в `config.yaml` по умолчанию `enabled: false` — приложение падает на старте, если коллектор включён, а его ключа нет. Включайте после того, как положили ключ в `.env`.

## 4. Быстрый старт

```bash
python app.py stats                                                # пустая БД, таблица с нулями
python app.py collect --source pexels --query "funny cats" --limit 10
python app.py collect --source all --query "funny dogs" --limit 20  # все включённые в config.yaml
python app.py fetch --urls urls.txt --limit 50                      # скачивание по списку URL
python app.py fetch --from-queue --watch                            # то же из очереди расширения (§5a)
python app.py process --detect-animals --check-quality              # probe → quality → dedupe → detect
python app.py dedupe --method phash                                 # near-dup по перцептивному хэшу кадров
python app.py compile --category dog                                # собрать шортс 1080×1920 (§5b)
python app.py export --format coco --output dataset/
python app.py stats --show-categories --show-sources
python app.py serve --host 0.0.0.0 --port 8000                      # FastAPI на :8000
python app.py prune                                                 # подмести файлы старых rejected (новые стираются сразу)
```

## 5. Формат `urls.txt`

Один URL на строку, пустые строки и строки, начинающиеся с `#`, игнорируются:

```
# короткие видео с животными
https://www.instagram.com/reel/XXXXXXXXX/
https://example.com/some-video

# закомментировано, не будет скачано
# https://example.com/skip-this
```

## 5a. Сбор ссылок расширением Chrome

Вместо ручного `urls.txt` ссылки можно собирать расширением из `browser_extension/`.
Оно кладёт их в локальную очередь, а качает всё тот же yt-dlp.

```bash
# 1. токен в .env (сгенерировать: python -c "import secrets;print(secrets.token_urlsafe(32))")
#    BROWSER_INGEST_TOKEN=...
# 2. browser_mode.enabled: true в config.yaml
python app.py browser-mode                        # сервер очереди + путь к расширению и токен
python app.py fetch --from-queue --watch          # в другом терминале: качает всё, что накопилось
```

Установка: `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное» →
папка `browser_extension/`. В попапе указать сервер и токен, при желании поправить
списки тегов, затем «Старт» на вкладке с лентой или страницей хэштега.

Как это работает:

- собирает ссылки обоих видов: `/reel/<код>/` и `/p/<код>/` (обычные видео-посты);
- на ленте и на сетке хэштега листает скроллом по одному посту, на открытом посте —
  жмёт стрелку «дальше» в просмотрщике; пауза 2–4 с, длинная пауза каждые 20 постов;
- останавливается сам: конец ленты, лимит постов, скрытая вкладка (кроме `browse` — там
  окна не видно и это не повод останавливаться), переполненная очередь;
- по тегам поста (и по хэштегу самой страницы, например `?q=%23funnyanimals`) решает,
  подходит ли видео; непохожее просто пролистывает;
- пост без подписи не отбраковывается, а откладывается до следующего круга;
- очередь смотреть в `GET /queue`, дубликаты отсекаются по shortcode.

### Без открытой вкладки: `app.py browse`

Держать вкладку открытой не обязательно — `browse` поднимает отдельный браузер со своим
профилем, сам грузит расширение и запускает его, а через заданное время закрывает.

```bash
python app.py browser-mode                        # 1) сервер очереди, отдельный терминал
python app.py browse --login                      # 2) один раз: окно, залогиниться в Instagram, закрыть
python app.py browse --minutes 30                 # 3) фоновый обход, окна не видно
python app.py fetch --from-queue --watch          # 4) качает всё, что накопилось
```

- `browse <url>` — какую ленту или страницу хэштега листать (по умолчанию
  `explore/tags/funnyanimals/`); `--show` — то же, но с видимым окном;
- профиль лежит в `browser_mode.profile_path` (`data/browser-profile`), куки после
  `--login` остаются в нём, так что вход нужен один раз;
- сервер и токен расширение получает из `browser_extension/session.json`, который
  команда пишет на время запуска и удаляет после (он в `.gitignore`);
- в конце печатает, сколько ссылок приняла очередь.

Нужен **Chrome for Testing или Chromium**: обычный Google Chrome с v137 игнорирует
`--load-extension` (пишет в лог `not allowed in Google Chrome, ignoring` и стартует без
расширения), поэтому команда его не берёт. Взять один из:

```bash
npx @puppeteer/browsers install chrome@stable     # либо brew install --cask chromium
python app.py browse --chrome /path/to/binary     # либо указать свой явно
```

Расширение не логинится за тебя, не обходит защиту и не имитирует поведение человека —
оно листает ленту в своей вкладке ровно так же, как в твоей. Автоматический доступ к
Instagram запрещён его ToS: решение за тобой.

## 5b. Сборка шортсов

`compile` подбирает из всех обработанных клипов пятёрку **с общей темой**, просит
**локальную модель** придумать заголовок, хук и подписи, и рендерит вертикальное видео
1080×1920.

```bash
brew install --cask ollama-app
ollama serve &            # http://127.0.0.1:11434
ollama pull qwen3:8b      # ~5 ГБ, ~43 tok/s на M4 Pro — тексты
ollama pull qwen2.5vl:7b  # ~6 ГБ — смотрит на кадр каждого клипа

python app.py compile                      # из всех категорий
python app.py compile --category dog       # только собаки
python app.py compile --count 3            # три шортса подряд, клипы не повторяются
python app.py compile --keep-work          # оставить промежуточные сегменты
```

Работают **две локальные модели**: `vision_model` (qwen2.5vl) смотрит на **три кадра**
каждого сегмента (10 %, 50 %, 90 % его длины) и одной фразой описывает, что там
**происходит**, а `model` (qwen3) из этих описаний делает заголовок, хук, строки ранкинга
и мемную подпись под каждым клипом. Без vision-прохода подписи — чистая выдумка: в БД у
рилсов пустые `tags` и `title` вида `Video by <author>`, класс животного от YOLO —
единственное, что известно. Vision недоступен (не скачан, Ollama лежит) — сборка не
падает, подписи просто становятся общими; выключить совсем: `vision_model: ""`.

Три кадра, а не один. По одному стоп-кадру из середины сегмента невозможно отличить
собаку в зумис от собаки, которая просто стоит, и все описания приезжали про мебель — «the
animal is lying on a bed with a plaid blanket». Шутка в ранкинге про такое описание — это
шутка ни о чём. Смешное в клипе — это то, что **меняется**, и три кадра по порядку —
первое, что даёт модели это увидеть.

По тем же трём кадрам модель **оценивает клип** (`rate_clip`, 0–4) — три вопроса `yes`/`no`
грамматикой, а не «оцени от 1 до 5» (на просьбу поставить балл модель ставит 3–4 всему
подряд, и такой рейтинг не сортирует ничего):

| вопрос | вес | что ловит |
|---|---|---|
| `funny` | **2** | происходит что-то неожиданное: попались на месте преступления, залезли куда не влезают, реагируют, пошло не по плану. Животное, которое все три кадра просто сидит, — `no`, каким бы красивым оно ни было |
| `human` | 1 | делает человеческое: одежда, стоит/сидит по-человечески, держит предмет как руками, пользуется мебелью, чашкой, экраном |
| `cute` | 1 | детёныш, крошечное, пушистое, прижимается к кому-то — и достаточно близко к камере, чтобы морда несла кадр |

`funny` весит вдвое: это подборка **смешного**, а милый клип, в котором ничего не
происходит, не даёт строке ранкинга повода для шутки. Vision выключен или недоступен —
клип получает 2, середину шкалы: без оценок порядок ровно тот же, что был, а один
сорвавшийся запрос не хоронит клип под всеми, кого модель не видела.

Клипы для подборки выбираются **по теме, а не по свежести**, и тему не сочиняют, а
считают:

1. каждому клипу пула модель ставит **два ярлыка из двух закрытых списков**:
   `_TAGS` — что животное делает (**34** штуки: `stealing food`, `sleeping`, `in water`,
   `running around wildly`, `stuck somewhere`, `startled`, `cuddling`, `dancing`, …),
   `_PROPS` — с чем оно это делает (**23** штуки: `fruit`, `a box`, `a mirror`, `a car`,
   `a hat`, `a blanket`, `a lap`, `another animal`, …), плюс `other` в обоих. Списки зашиты
   в JSON-схему как `enum`, то есть в грамматику декодирования — ответ вне списка невозможен
   физически. Две оси, а не одна: пять животных, которые по-разному воюют с фруктом, —
   такая же честная подборка, как пять ворующих, и корзин ≥5 клипов на текущем пуле
   становится 13 вместо 7.

   Ярлыков было 20 и 15, и на пуле в 208 клипов они оставляли **43 клипа в `other`**, а
   самой полной корзиной было `watching something` — 27 клипов «животное на что-то
   смотрит», самый скучный шортс, который эта машина умеет собрать. Все добавленные ярлыки
   называют **действие**: три кадра вместо одного наконец сделали движение видимым для
   модели, и списку стало чем его называть;
2. **группировка — обычный Python**, не модель: клипы раскладываются по обоим ярлыкам в
   одну кучу корзин, берётся **лучшая**. Так «TOP 5 …» верен про все пять
   **по построению**. Ярлык, на котором уже собран шортс этой пачки, пропускается целиком:
   иначе самая большая корзина пула называет два ролика подряд и оба получают одну и ту же
   рубрику над разными клипами;

   **Лучшая, а не самая полная.** По размеру корзина из 27 «смотрит на что-то» побеждала
   корзину из шести «проигрывает бой с одеялом» всегда, и ролик выходил про пятерых
   неподвижных животных под рубрикой, обещавшей отсчёт. Теперь корзина стоит столько,
   сколько стоят её **лучшие `size` клипов** по `rate_clip`, а число клипов только разбивает
   ничью. Внутри корзины тот же порядок решает, кто попадёт в ролик: кандидаты идут от
   высшей оценки к низшей, так что в подборке — **лучшие пять этой темы**, а не пять
   последних скачанных. Равные по оценке остаются в порядке пула (свежие первыми);
3. **каждого кандидата переспрашивают** (`fits_tag`, ответ `yes`/`no` грамматикой):
   ярлык ставился одним выстрелом при `temperature 0` и промахивается — какаду напротив
   кота приезжал с ярлыком `a toy`. Корзина `a toy` из 18 клипов на проверке ужимается до
   трёх, и тогда берётся следующая по размеру. Так в подборку не попадает клип,
   про который заголовок соврёт;
4. одиночный ярлык кончился — берётся **семья ярлыков** (`_FAMILIES`, их 12): «воры» — это
   `stealing food` + `hiding` + `escaping` + `a shoe` + `a bag`, «еда» — `eating`,
   `drinking`, `fruit`, `junk food`, `a drink`, `licking something`, «притворяются людьми» —
   `wearing clothes`, `standing on hind legs`, `riding something`, `sitting like a person`,
   `dancing`, `a hat`, `a mirror`, `a screen`. Плюс вода, лежебоки, хаос, игрушки,
   обнимашки, «испугались или застряли», «требуют от человека», «быстро двигаются» и
   «пялятся». Ключ семьи — **фраза, про которую спрашивают каждый клип** тем же
   `fits_tag`, поэтому клип, случайно попавший в один из ярлыков, в семью не проезжает.
   Семьи идут **после** одиночных ярлыков, а не вместо: «TOP 5 SNACK BANDITS» про пятерых
   воров смешнее, чем «TOP 5 HUNGRY LEGENDS» про всех, кто рядом с едой, — зато семья
   даёт тему там, где ни один ярлык уже не набирает пяти клипов;
5. корзины кончились (к концу пачки из 19 шортсов действия расходятся) — группируем по
   **виду животного**: «TOP 5 CERTIFIED CATS» честен про пять котов, какими бы разными они
   ни были. Вид берётся с двух сторон: слово от vision (`chipmunk`) и класс детектора
   (`dog`, `cat`, `bird` — YOLO знает девять животных, зато его корзины единственные, где
   к концу пачки ещё лежит по пять клипов). Класс детектора врёт достаточно часто, чтобы
   каждый кандидат проходил тот же `fits_tag`. Не хватило и этого — **ярлык берётся
   повторно**: пачке из 19 шортсов нужно больше тем, чем в пуле ярлыков, и второй ролик по
   `sleeping` на других пяти клипах лучше, чем шесть роликов подряд с рубрикой
   `Funny Animals`. Повториться нельзя названию — оно тоже лежит в `done`, и заголовок,
   уже занятый в этой пачке, отправляется на переписывание. Совсем пусто — рубрика
   становится нейтральной `Funny Animals`;
6. название темы пишет qwen3 («Snack Bandits», «Fruit Feasts») — три попытки, каждая
   проходит пять дешёвых проверок и одну дорогую:
   - множественное число в последнем слове («TOP 5 GRAZE SQUAD» — это опечатка на экране);
   - заголовок ≠ сам ярлык («TOP 5 STANDING ON HIND LEGS» — это подпись, а не название);
   - **выдуманное слово** (`_made_up`, `/usr/share/dict/words`): «TOP 5 PROFESSIONAL
     STARELERS» — модель сама изобрела существительное. Список 1934 года, поэтому слово,
     собранное из настоящего живым суффиксом (`snackers`, `selfies`), считается настоящим,
     а британское написание сверяется с американским (`neighbours` → `neighbors`);
   - пустышки (`ACTS`, `FUN`, `MOMENTS`, `VIBES`) и название вида;
   - **предмет из одного клипа** (`_in_one_clip`): слово, которое есть ровно в одном
     описании из пяти, — враньё про остальные четыре («CAKE OBSERVERS»). Слова самого
     ярлыка исключены: описания vision слишком разные по лексике, чтобы «hind» встретилось
     больше чем в одном описании пяти животных, стоящих на задних лапах;
   - последним идёт **сам ЛЛМ** (`heading_holds`): пять описаний плюс готовый заголовок,
     ответ `yes`/`no`. Только он ловит деталь, которой нет **ни в одном** клипе, —
     «MIRROR LOVERS» над пятёркой без единого зеркала.

   Все три попытки мимо — берётся заранее написанное для этого ярлыка (`_HEADINGS`).

Одним запросом «выбери пять и назови тему» это не решается: в пяти прогонах модель пять
раз вернула одну и ту же тему и добила пятёрку клипами, которые к ней не относятся.

Внутри пачки клипы не повторяются, **пока их хватает**: 19 шортсов — это 95 слотов на пул
из 96 клипов, и последние ролики выбирают из горстки, у которой нет ничего общего. Пока
неиспользованных клипов больше трети пула, шортс собирается только из них; ниже —
возвращается весь пул. Один клип в двух подборках под двумя разными темами лучше, чем пять
роликов подряд с рубрикой «TOP 5 FUNNY ANIMALS».

Описания, оценка и оба ярлыка кэшируются в `data/vision.json` по id видео: пул
пересматривается на каждый шортс, а один взгляд — это ~15 с локального инференса. Ярлыки
читают **описание, а не кадр**, поэтому кэш, записанный до появления второй оси,
дописывается одним дешёвым текстовым проходом, без повторного взгляда. У записи есть
версия (`"v"`): записи версии 1 — один кадр и без оценки — пересматриваются целиком, то
есть **первый запуск после обновления пересоберёт весь кэш** (208 клипов ≈ час локального
инференса, один раз). Кэш пишется на диск **после каждого прохода**, а не в конце: терять
час инференса из-за падения на последнем клипе — не то, о чём хочется узнать. Кэш можно
просто удалить, он соберётся заново.

Проходов по пулу **два, а не по одному визиту на клип**: сначала всё, что читает пиксели
(описание, оценка, чужие титры), потом модель зрения **выгружается** (`keep_alive: 0`), и
только потом идут ярлыки, которые читают описание. Обе модели ~6 ГБ: если чередовать их
клип за клипом, машина уходит в своп — запрос, который в норме занимает 1 с, шёл
**15 минут**.

Модели работают локально, в интернет ничего не уходит. Текстовая отвечает **только JSON** —
схема (`format` в Ollama API) превращается в грамматику декодирования, поэтому лишний
текст и неверное число подписей невозможны в принципе. Модель не трогает сам рендер:
резка, фон и наложение текста — ffmpeg и Pillow, ошибка модели не может испортить видео.

Как собирается сегмент:

- начало реза — по первой детекции животного минус 1 с (из таблицы `detections`),
  а не с нулевой секунды, где у рилсов обычно заставка;
- фон — размытая копия того же кадра в cover, поверх — клип целиком в fit;
- тексты рисует **Pillow**, а не `drawtext`: локальный ffmpeg собран без libfreetype,
  плюс Pillow умеет перенос строк и обводку, чего `drawtext` не умеет вовсе;
- все сегменты кодируются одинаково (1080×1920, 30 fps, h264, aac 48k stereo);
- у клипа без звуковой дорожки берётся дорожка другого клипа этой же подборки — ровно
  тот кусок, который в подборке и показан, зациклённый под длину сегмента; нет доноров
  со слышимым звуком — тишина, иначе склейка теряет звук.

Раскладка текста:

- **сверху — рубрика** `TOP 5 <тема>`: число берётся из количества клипов, поэтому
  зритель, попавший на середину, видит, что есть отсчёт, ради которого стоит досмотреть.
  Тема — та, по которой клипы и отбирались, так что рубрика верна про все пять.
  Модель половину раз пишет «TOP 5» и внутри самой темы — этот префикс срезается;
- **под рубрикой — призыв мелким шрифтом** (`cta`, кегль `cta_size`): «LIKE IF YOU LOVE
  <тема> TOO». `{category}` в шаблоне заменяется темой, пустая строка убирает призыв
  совсем. Рисуется тем же слоем, что и рубрика: у фиксированного `y` он налезает на
  вторую строку заголовка, который перенёсся («TOP 5 PROFESSIONAL LOUNGERS»);
- **слева по центру — ранкинг из 5**: строки открываются по ходу ролика — на втором
  клипе подписаны только 1 и 2, у 3–5 стоят голые цифры (интрига). Текущая подсвечена
  жёлтым, пройденные приглушены. Строка 1 — клип с лучшей оценкой, и он же открывает
  шортс: зритель уходит на первых секундах, и держать лучший кадр на пятой позиции —
  значит показать его тем, кто и так досмотрел;
- строка **гарантированно влезает в одну линию**: под самую длинную из пяти подбирается
  кегль (до 70 % от `ranking_size`), а если и этого мало — отбрасываются целые слова;
  многоточие остаётся только для одного слишком широкого слова. Резать по символам
  бессмысленно: 26 «W» — это 1003 px при лимите 669;
- подписи — **шутки**, 2–4 слова, привязанные к тому, что реально в кадре («STOLEN
  STRAWBERRY SNEAK», «HAND HELD CRIMINAL»). Аллитерация и рифма запрещены промптом:
  выбирая слова на одну букву, модель выдаёт скороговорку вместо шутки («BOW BURDENED
  BADDY»), и все пять строк начинают выглядеть одним шаблоном;
- **снизу — своя мемная подпись у каждого из 5 клипов** (до 8 слов, «EATING THE
  EVIDENCE»); на первом клипе вместо неё хук. Запрос **на каждый клип отдельный**: если
  просить пять подписей разом, модель держит порядок строк ранкинга, но плывёт по
  содержанию — подпись про кота оказывается под сурикатами. Повторила строку ранкинга —
  один переспрос, и если снова то же, клип идёт без нижней подписи: одна и та же фраза
  дважды на кадре читается как баг рендера.

Порода животного намеренно **не доходит** до текстовой модели: получив её, qwen3 начинает
каждую строку с вида — «CHIHUAHUA STRAWBERRY THIEF», «CAT WATERMELON GHOST» — сколько бы
раз промпт это ни запрещал. Поэтому vision-модель описывает кадр, называя объект просто
«the animal», а класс YOLO уходит в промпт только когда vision недоступен и больше нечего
дать. Зритель и так видит, кто в кадре, — шутка начинается после названия.

Звук и переходы:

- между клипами кроссфейд `xfade`+`acrossfade` на `transition_seconds` (0.35 с),
  поэтому итог короче суммы сегментов: 5 × 8 − 4 × 0.35 = **38.6 с**;
- звук у каждого клипа **свой**, выровненный по громкости (`loudnorm` до −16 LUFS):
  рилсы приходят от −30 до 0 dBFS, без этого один клип орёт после другого;
- перед `loudnorm` стоит **обрезной фильтр 90 Гц**. Рилсы с рук набиты инфранизким
  гулом от тряски: у одного из клипов **97 % энергии лежало ниже 80 Гц** — телефон это
  не воспроизводит, а `loudnorm` тратил на него весь запас усиления, и клип звучал как
  сплошной шум. По этой же причине громкость меряется **после** фильтра — иначе гул
  делает клип «самым громким» и именно он идёт в доноры;
- немому клипу дорожку **подбирает модель**: ей показывают, что vision увидел в немом
  клипе и в каждом из озвученных, и она выбирает ближайший по настроению и энергии
  (спокойной сцене — спокойный трек). В кандидаты попадают только клипы громче −35 dBFS
  по слышимому диапазону. Модель недоступна — берётся первый донор;
- музыкальная подложка (`music_volume`) по умолчанию **выключена**. Исходники уже
  сидят у 0 dBFS, поэтому второй трек сверху клиппил в грязь, а на клипе-доноре
  накладывался сам на себя (гребёнка) — это и был «странный шум». Нужна подложка —
  поставьте `music_volume: 0.15`, сумму ловит `alimiter`;
- `transition_seconds: 0` выключает переходы (тогда склейка идёт быстрым `concat`).

Настройки — секция `compiler` в `config.yaml` (модель, число клипов, длина сегмента,
переход, громкость подложки, шрифт, кегли: `title_size` рубрика, `caption_size` хук,
`ranking_size` список, `cta`/`cta_size` призыв под рубрикой).

**Где искать результат:** `data/shorts/{slug-заголовка}.mp4` — например
`data/shorts/doggo-drama.mp4`. Открыть папку в Finder: `open data/shorts`.
Одинаковые заголовки не затирают друг друга: второй файл станет `...-2.mp4`.

**Память между запусками — `data/compiled.json`.** Внутри одного `compile --count N`
использованные клипы и темы не повторяются, но раньше этот список жил только до конца
процесса: следующий запуск начинал с пустого и снова брал самый полный бакет — те же пять
клипов под тем же заголовком, файл `top-5-toy-destroyers-2.mp4`. Теперь `recall()`/`keep()`
держат оба множества на диске. Пул при этом не голодает: `build_short` возвращается ко
всему пулу, когда неиспользованных клипов остаётся меньше трети, а `group_clips` заново
проходит по ярлыкам с пустым `done`, когда все разобраны (тогда заголовок будет
«More …»). Удалить файл — значит разрешить сборку тех же тем заново.

## 5c. Отбраковка чужих нарезок

В датасете нужны **только цельные ролики с животным**, а не чужие «ТОП-10» и подборки.
`process` режет их двумя воротами, до детекции:

| `reject_reason` | Что ловит | Как |
|---|---|---|
| `compilation` | подборка, склеенная из чужих клипов | `count_cuts()` считает жёсткие склейки фильтром ffmpeg `select='gt(scene,0.4)'`; больше `processing.video.max_cuts` (по умолчанию 1) — в брак |
| `burned_text` | **любой** вшитый текст или логотип: чужой заголовок, список, `@ник`, вотермарка TikTok/Instagram, имя приложения в углу | тот же vision-вопрос `has_text()`, что и при сборке, но задаётся по **каждому кадру** клипа |

Порог 0.4 и `max_cuts: 1` откалиброваны на пуле из 96 клипов: у 86 из них склеек нет
совсем, а у каждой известной подборки их от 2 до 28 (у «Top 10 Funniest Cats» — 8).
Склейки считаются **до** нормализации, чтобы на нарезку не тратился транскод; vision-вопрос
идёт последним из фильтров — он единственный стоит вызова модели. Ollama недоступна —
`has_text()` отвечает «нет», и ролик остаётся (не теряем клипы из-за лежащей модели).

Вопрос раньше заканчивался словами «мелкий ник или логотип не считается», и именно эта
фраза пропустила в готовый шортс вотермарку TikTok (`@poe5199`) и угловое «Dola AI».
TikTok режет охват ролику с чужой платформенной меткой, поэтому теперь считается **всё
вшитое, каким бы мелким оно ни было**. Читается **каждый** кадр, а не выборка из трёх:
кадры снимаются раз в две секунды, и подпись «All I said was good morning...» на 14-секундном
клипе лежала ровно между первым, средним и последним — так она и попала в готовый шортс.
`any()` обрывается на первом «да», так что брак стоит одного вызова; по всем кадрам платит
только чистый клип.

Те же ворота стоят и на сборке (`src/compiler/__init__.py`): клип с вшитой надписью
выкидывается из пула перед группировкой — это подстраховка для роликов, скачанных до
появления фильтров. Флаг лежит в кэше `data/vision.json` рядом с ярлыками.

## 7. API

`python app.py serve` поднимает FastAPI на `http://localhost:8000`, интерактивная документация — `/docs`.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/stats` | Общая статистика, с разбивкой по категориям и источникам |
| GET | `/videos` | Список с фильтрами (`source`, `category`, `min_duration`, `max_duration`, `has_animal`, `license`, `status`) и пагинацией (`page`, `per_page`) |
| GET | `/videos/{id}` | Метаданные одного видео, 404 если нет или удалено |
| GET | `/videos/{id}/file` | Файл видео |
| DELETE | `/videos/{id}` | DMCA-удаление: файл/превью/кадры стираются с диска, запись помечается `status=deleted` |
| POST | `/queue/urls` | Только при `browser_mode.enabled`: приём ссылок от расширения, заголовок `X-Ingest-Token` |
| GET | `/queue` | Только при `browser_mode.enabled`: что ещё не скачано |

## 8. Docker

```bash
cp .env.example .env   # заполнить ключи, опционально
docker compose up --build
```

Поднимает `app` (FastAPI + CLI-образ) и `db` (`postgres:16-alpine`). `app` ждёт готовности БД (healthcheck `pg_isready`) перед стартом. Данные и веса модели живут в `./data`, смонтированной как volume — переживают пересоздание контейнера.

## 9. Экспорт

```bash
python app.py export --format coco --output dataset/
python app.py export --format webdataset --output dataset/
python app.py export --format huggingface --output dataset/ [--push]
```

- **coco** — `images`/`annotations`/`categories` из таблицы `detections`, train/val сплит детерминирован (`sha256(source:source_id) % 100`).
- **webdataset** — tar-шарды по 1 ГБ (`{key}.mp4` + `{key}.json`).
- **huggingface** — `datasets.Dataset`, `--push` требует `HF_TOKEN` в окружении.

По умолчанию записи с `license: unknown` (в основном из `fetch`/yt-dlp) **исключаются** из экспорта — лицензия неизвестна, распространять нельзя. Чтобы включить их явно: `--include-unlicensed`.

## 10. Как добавить свой источник

1. Создать файл `src/collectors/<name>.py`.
2. Класс-наследник `BaseCollector` с декоратором `@register` и реализацией `async def search(...)`.

```python
from src.collectors.base import BaseCollector, register

@register
class MyCollector(BaseCollector):
    name = "mysource"

    async def search(self, query: str, limit: int):
        ...
```

Коллектор подхватывается автоматически (автодискавери пакета `src/collectors/`) — правок в других файлах не требуется. Включается/выключается через `config.yaml: collectors.mysource.enabled`.
